# M0: Foundation and terrain

M0 produces no game. It produces the frame every later module is built in: a seeded map on screen, a sim running in a worker behind a command bus, and a city that saves, reloads and exports.

The full context is in [the PRD](../PRD.md), under "Technical architecture" and "M0 Foundation and terrain".

## Exit test

All of these pass in one Playwright walkthrough, on WebGPU where available and on the WebGL 2 fallback.

1. Open the page. A 12 km map generated from a seed renders within 5 seconds.
2. Orbit, pan and zoom. Clicking the ground reports world coordinates in the debug panel.
3. The debug panel shows the sim ticking at 10 ticks per second. Pause, 1x, 2x and 4x change the rate.
4. Send a no-op command. It appears in the activity log with a player id and a tick.
5. Reload the page. The same city comes back at the same tick, from IndexedDB.
6. Download the city as a file, clear site data, import the file. The same city comes back.
7. A replay of the recorded command log from the same seed produces the same state hash.

## Numbers fixed for M0

| What | Value |
| --- | --- |
| World unit | 1 metre |
| Map | 12,000 m square |
| Heightmap | 750 x 750 samples, 16 m apart |
| Chunks | 500 m square, so 24 x 24 |
| Sim tick | 100 ms of game time, 10 per second at 1x |
| Speeds | pause, 1x, 2x, 4x |
| Tick budget | 20 ms of worker time |
| Local save | IndexedDB |
| City file | one file, extension `.city` |

  Decided in issue 11: GitHub Pages. Nothing in M0 needs a header Pages cannot send, and `SharedArrayBuffer`, the one thing that would, is not used. The reasons are in the PRD under M0.

## Out of scope

Roads, zoning, buildings, pops, money, overlays, multiplayer, accounts, sound. Terraforming is out of v1 entirely. If something here seems to need one of these, it belongs to a later milestone.

## One risk to settle early

A save stores the seed, not the heightmap. In multiplayer the server and every client will each rebuild terrain from that seed, so the result has to be identical on every engine. Issue 05 restricts terrain code to exact operations and proves it with a hash checked in both Node and the browser. If that proves too tight a constraint, the fallback is to store the heightmap in the snapshot and accept a larger save.
